نظام مدار لإدارة المدرسة
نظام إدارة مدرسة محلي مبني بلغة PHP وقاعدة بيانات MySQL، ومصمم للعمل على XAMPP في Windows. الواجهة عربية RTL، متجاوبة مع الهاتف، وتحتوي على لوحة تحكم، طلاب، معلمين، فصول، حضور وغياب، ومدفوعات.
المتطلبات
يحتاج النظام إلى XAMPP مع تشغيل Apache وMySQL، ومتصفح حديث مثل Chrome أو Edge، ومحرر مثل VS Code. يعمل النظام محليًا ولا يحتاج إلى استضافة أو اتصال خارجي.
التثبيت على Windows
فك ضغط مجلد المشروع باسم `school_manager` داخل:
```text
C:\xampp\htdocs\school_manager
```
افتح XAMPP Control Panel وشغّل Apache وMySQL.
افتح:
```text
http://localhost/phpmyadmin
```
من phpMyAdmin اختر تبويب Import، ثم اختر الملف `database.sql`، واضغط Go. سينشئ الملف قاعدة `school_manager` والجداول والعينات والحساب الافتراضي.
افتح النظام:
```text
http://localhost/school_manager/login.php
```
بيانات الدخول التجريبية:
```text
اسم المستخدم: admin
كلمة المرور: admin123
```
غيّر بيانات الدخول في أي نسخة حقيقية، ولا تترك كلمة المرور التجريبية.

طريقة الاستخدام
بعد تسجيل الدخول ستظهر لوحة التحكم وفيها عدد الطلاب والمعلمين والفصول وحضور اليوم. من القائمة الجانبية يمكنك فتح الطلاب، ثم اختيار طالب جديد لفتح النموذج. احفظ الرمز والاسم والجنس واربط الطالب بفصل، ثم استخدم زر التعديل لاحقًا لتغيير البيانات.
من صفحة المعلمين أضف اسم المعلم وتخصصه ووسائل الاتصال. ومن صفحة الفصول أنشئ الفصل والمرحلة ورقم الغرفة؛ وستحسب الصفحة عدد الطلاب المرتبطين بكل فصل تلقائيًا.
في صفحة الحضور اختر الطالب والتاريخ والحالة. إذا سجلت الحالة نفسها للطالب والتاريخ نفسه مرة أخرى، سيحدث النظام السجل بدل إنشاء تكرار؛ لأن قاعدة البيانات تضع قيدًا فريدًا على الطالب واليوم.
في صفحة المدفوعات اختر الطالب وأدخل المبلغ والتاريخ والوصف. يعرض النظام إجمالي المدفوعات وآخر العمليات.
شرح الاتصال بقاعدة البيانات
يستخدم `config.php` PDO مع `PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION` كي تظهر أخطاء قاعدة البيانات أثناء التطوير، ومع `PDO::ATTR_EMULATE_PREPARES => false` كي تستخدم الاستعلامات المجهزة بالطريقة الصحيحة. كل القيم القادمة من النماذج تمر إلى `prepare()` و`execute()` ولا تُدمج مباشرة داخل SQL.
الحماية المستخدمة
يستخدم النظام `password_hash()` لتخزين كلمات المرور، و`password_verify()` لفحصها. يستخدم `htmlspecialchars()` داخل الدالة `e()` قبل عرض النصوص في HTML، ويستخدم رمز CSRF في النماذج المهمة، ويتحقق من الجلسة عبر `requireLogin()`، ويستعمل استعلامات PDO مجهزة لتقليل خطر SQL Injection.
هذه حماية تعليمية جيدة لنظام محلي، لكنها ليست مراجعة أمنية كاملة لنظام إنتاج. قبل نشر النظام يجب إضافة صلاحيات تفصيلية، وتحديد إعدادات الخادم، وإجبار HTTPS، وتغيير الحساب الافتراضي، وتسجيل العمليات، وحماية رفع الملفات إن أضيف لاحقًا.
إذا ظهر خطأ في الاتصال
تأكد من تشغيل MySQL في XAMPP، وأن اسم القاعدة هو `school_manager`. إذا كانت لديك كلمة مرور لمستخدم `root`، افتح `config.php` وغيّر قيمة `$dbPassword`. إذا ظهر أن الجدول غير موجود، أعد استيراد `database.sql` من phpMyAdmin.
ملاحظات للمطور المتعلم
ابدأ بقراءة `config.php` ثم `functions.php`، وبعدها اتبع تدفق الطلاب: `students.php` يستقبل العرض، و`student_save.php` يعالج POST، و`student_delete.php` يحذف السجل. لاحظ كيف ينتقل المتغير `$pdo` بين الملفات، وكيف تنتقل القيم عبر `$_POST`، وكيف تستخدم `$_SESSION` بيانات الدخول والرسائل المؤقتة.
الاختبار اليدوي المقترح
اختبر تسجيل الدخول بكلمة صحيحة وخاطئة، ثم أضف طالبًا جديدًا وعدّل اسمه واحذفه. جرّب البحث باسم جزئي، وسجّل حضور طالب مرتين في اليوم نفسه، وأضف دفعة، ثم أغلق MySQL وحاول فتح الصفحة لترى رسالة الاتصال العامة. أخيرًا اختبر عرض اسم يحتوي على الرموز `<` و`>` للتأكد من أنه يعرض كنص وليس ككود HTML.
